# ADR-005 — Future laboratory module boundary
Status: Proposed
Date: 2026-09-10
Related requirements: FOUND-009
Related tasks: TASK-015
Decision owner/acceptance evidence: project owner / pending

## Context
Owner requests architecture readiness, not a lab product implementation.

## Options
A. Document future lab module and explicit use-case interfaces now (recommended). B. Implement speculative lab tables/API/SDK now adds unapproved scope. C. Couple future provider access directly to patient tables undermines module ownership.

## Proposed decision
Reserve conceptual module ownership and describe explicit authorized patient/encounter reference lookup plus outbound provider adapters owned by a future lab module. Vendor/protocol, request/result schema, credentials, identity mapping and delivery state machines await future approved requirements. No runtime stub or schema extension now.

## Consequences and validation
Walk through future request and result scenarios for identity, authorization, idempotency, acknowledgement/retry/reconciliation and audit ownership. No live integration or interoperability/compliance claim.
No implementation or deletion is approved by this record. See [baseline](../BASELINE.md) and [findings](../../Assessment/INITIAL_ASSESSMENT.md).
