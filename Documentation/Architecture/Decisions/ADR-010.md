# ADR-010 — Local packaged deployment boundary
Status: Accepted for owner-approved TASK-027 local synthetic scope, 2026-09-13.

Use one pinned Node 24 build to produce compiled API and React Native Web assets. Run separate non-root API and static-web/proxy containers plus PostgreSQL mcclinic through isolated Docker Compose. Publish only web on 127.0.0.1; API/DB use the Compose network. No Vite at runtime. Persist database and onboarding mailbox/key separately. Migrations are an explicit one-shot command before API startup; no automatic destructive rollback or volume purge.

The web container proxies exact API/health paths, strips unsafe forwarding headers, disables clinical/API caching and serves immutable hashed static assets. Configuration explicitly permits local-container with synthetic opt-in; staging and production fail closed pending TASK-028/029. This does not approve ADR-008/009 AWS topology, RPO/RTO or public exposure.

LocalStack remains optional and is not installed or started. It offers value when AWS-specific adapters exist; it is not a dependency for application/container validation. Cloud deployment, external mail/key custody, least-privilege cloud migration roles, TLS ingress and actual AWS resilience remain separate tasks.

Tradeoff: one shared build image simplifies reproducibility and matching releases but includes build tooling; a production dependency-minimized image can be separately assessed. Record SBOM and scan limitations rather than calling the image hardened or compliant. Containers bind internally to 0.0.0.0; Docker publishes web on loopback only. Existing loopback entry points remain unchanged.
