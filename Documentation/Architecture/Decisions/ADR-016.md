# ADR-016 — Local dotenv at configuration entry points

Accepted for TASK-041 synthetic development, 2026-09-21. Repository-root .env is optional and resolves from installed source/build location rather than shell cwd. Explicit environment always wins. Load only for local development (not production/test/CI or nonlocal APP_ENV); preserve validation and runtime injection. No dotenv in clinical domain code or browser bundle. Prisma/local seed/rename share the loader; packaged/staging entry points do not import it. Safe .env.example and setup docs; no existing secret file overwritten. This extends local convenience, not cloud secret custody or legal readiness. Official behavior: https://github.com/motdotla/dotenv.

Implementation detail: Vite's Node-only config loads into a copied environment and uses only EHR_API_TARGET; root dotenv variables are not promoted into Vite's client environment. Production Prisma lazily avoids importing the local helper, so the hardened migration image remains independent of local source/dotenv loading. Existing exported env and explicit VITE_* behavior are preserved.
