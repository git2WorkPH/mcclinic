# ADR-007 — Local onboarding, email tokens and MFA
Status: Accepted for owner-approved development scope, 2026-09-12.
Use email as normalized username for newly registered accounts, retain nullable email for legacy seeded accounts. Registration verifies email before access. An optional initial practice is created atomically on verification, with clinician/manager membership and SOLO trial. Invite-only staff may register without creating a practice and accept their scoped invitation after verification.
Use random 256-bit link tokens, SHA-256 hashes, expiry/consumption timestamps, per-account transactional locks and persistent fixed-window abuse counters. Local outbound messages use a private ignored directory; no public mailbox endpoint and no external delivery. Failed delivery is surfaced generically and can be retried by resending.
TOTP: 30-second HMAC-SHA1 six-digit codes with +/- one time-step skew, encrypted secret, anti-replay step and hashed one-time recovery codes. Enrollment/disable require password; reset requires existing MFA, preventing email-only bypass. MFA enable/disable/reset revoke sessions. Local AES-256-GCM key is generated in ignored .local/onboarding-key with mode 0600 and must be retained alongside database backups; no production key-management claim.
All identity operations and audits are atomic; invitations verify recipient email, current manager authority and clinician seats in the practice transaction. No implicit platform support or clinical entitlement. Real mail/service identity/MFA policy decisions remain production work.
Database canonical name is mcclinic. Change new-service defaults and provide maintenance-connection ALTER DATABASE RENAME that refuses an existing target and never terminates sessions or drops data. Existing connection credentials and volumes are preserved. No active DATABASE_URL was exposed to this session; do not guess a live database to rename.

Reset links bind to the user credential version. Any successful reset or MFA change invalidates older outstanding reset links; session creation rechecks the version under the user lock to prevent a login racing credential rotation.
