# ADR-014 — Offline staging foundation preparation

Status: Accepted for local preparation only, 2026-09-20; TASK-028 owner-approved sequence and explicit no-AWS-spending instruction. ADR-008/009 production/deployed acceptance remains Proposed.

Use CloudFormation to make foundational resources reviewable without an account or apply. Split Singapore private data/runtime foundation from us-east-1 CloudFront-scope WAF access policy. Use private interface endpoints rather than NAT/public task addresses as the provisional egress candidate. This changes the earlier no-NAT cost assumptions: five endpoint services across two AZs add costs that must be recalculated before any budget acceptance. No free-tier discount or original $105 ceiling is assumed valid for this variant.

The foundation contains no active ECS service, ALB or CloudFront distribution. It deliberately has no inbound runtime rule or internet gateway. Private database/storage/key policies and edge policy can be validated independently before routing and staging-runtime work. These templates are not a complete deployable application. Required follow-up: ingress/TLS/origin controls, zero-cache API routing, staging entry point, task/migration definitions, runtime database role/bootstrap, durable sink mounts, anomaly/operational alarms, release artifacts and deployed checks.

Retain data, keys, registry images and logs; do not add lifecycle deletion. The proposed seven-day RDS PITR window is operational backup configuration, not a clinical retention rule; automated backup expiry and retained snapshot strategy require explicit operational acceptance before apply. No resource is provisioned by this decision. CloudFormation retention settings are defense in depth, not permission for teardown or replacement.
