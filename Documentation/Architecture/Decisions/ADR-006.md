# ADR-006 — Development SaaS practice isolation and snapshots
Status: Accepted for v0.3 development scope, 2026-09-11, under owner authorization.

Shared PostgreSQL schema, explicit practice IDs and verified membership in every application transaction. Scope repositories centrally with explicit typed practice context; clinical use cases retain role checks. The existing User.role is retained for migration compatibility only; authenticated roles come from memberships. Default practice receives all existing records through column defaults without rewriting immutable audit/version rows. Composite tenant foreign keys supplement application isolation.

RLS assessment: valuable defense in depth but deferred for development. The current migration/test connection owns the database and bypasses ordinary RLS; a production rollout needs a separate non-owner app role, FORCE RLS policy review and pooled transaction context tests. Do not claim RLS protection. Require negative cross-tenant tests across every exposed feature. No direct Prisma access from clinical use cases.

Guided template definitions use allowlisted plain-text tokens and escaped output, never executable HTML. Published revisions append; issued documents retain rendered HTML and configuration/value snapshots so subsequent settings cannot change them. Legacy issued snapshots retain legacy renderer fallback. No legal signature capability.

Subscriptions use a local simulated adapter. Billing never grants clinical permissions. Restricted subscriptions block new clinical/demographic/scheduling writes but retain authorized reads, print and role-limited export; administrators can simulate recovery. Seats count active clinician memberships, locked per practice for concurrent changes. No automatic deletion.

No public platform-administration API: local account provisioning only, and practice admins can assign memberships to existing synthetic accounts. Self-service identity onboarding/email and real payment provider integration remain separate production work.

Review refinements: a creator receives an explicit management grant separate from clinical role, so a solo clinician can manage their own practice. The server revalidates both role and grant. Platform identity audits are stored in an internal practice without memberships, never exposed to clinic administrators. Template preview uses the same configured full-document renderer with synthetic patient/medication data. Clinical transactions share the practice lock with membership, template publication and billing changes to avoid check/use races.
