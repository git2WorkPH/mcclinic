# ADR-012 — Separate serving and migration artifacts

Status: Accepted for local synthetic development, 2026-09-14, within owner-approved TASK-035. No cloud/production acceptance.

Add a full build/migration image and distinct API/web serving targets. Serving targets contain pinned Node 24.21.0, reviewed bundled JS, required schema/static assets, runtime base libraries and generated provenance; they omit build/native tools by construction. Original Dockerfile/package remains available. No internal microservices: the API remains a modular monolith and web remains its frontend/proxy.

Use an official pinned Debian 12 non-root distroless C/C++ base compatible with the pinned Node binary. Run UID 1000 to preserve existing state-volume ownership. Explicit ESM bundling preserves source-relative asset locations; dynamic/optional native dependencies must be covered by runtime verification. Migration/seed uses the preserved full package so schema evolution is independent of serving startup.

Tradeoffs: bundled stack traces/module paths need provenance; scanned code dependency inventory must accompany OS scanning because package.json files are not the runtime dependency tree. Reject unsupported external bundle imports except known Node builtins/optional pg-native; test actual migrations, browser workflows, audit/versions and restored MFA keys. No vulnerability suppression or production-risk acceptance. Rollback keeps older artifacts and current additive schema.
