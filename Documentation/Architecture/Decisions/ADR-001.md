# ADR-001 — Feature-owned modular monolith and workspace layout
Status: Proposed
Date: 2026-09-10
Related requirements: FOUND-001, FOUND-002
Related tasks: TASK-001
Decision owner/acceptance evidence: project owner / pending

## Context
PROJECT.md illustrative global packages conflict with the installed architecture skill. User requires Clean Architecture and a modular monolith.

## Options
A. Feature-owned domain/application/adapters in one API deployment with focused shared packages (recommended). B. Global domain/application packages: easy initial grouping but weak feature ownership. C. Microservices: added operational/distributed complexity without an approved need.

## Proposed decision
Use apps/api/src/modules/{patient,consultation,prescription,medical-certificate,appointment,identity,audit}, each with domain/application/adapters/infrastructure as needed. A composition root wires dependencies. Use apps/clinical-app with feature UI folders. Create packages only for actual cross-consumer contracts, validation primitives or test support. Keep Prisma schema/migrations under API persistence infrastructure; final physical paths are settled in bootstrap. No empty speculative feature implementation.

## Consequences and validation
Validate import direction with checks and one synthetic use-case/adaptor example; verify GraphQL-generated contracts remain distinct from Prisma. User stack is fixed; Node 24 is inherited technical baseline pending compatible version resolution.
No implementation or deletion is approved by this record. See [baseline](../BASELINE.md) and [findings](../../Assessment/INITIAL_ASSESSMENT.md).
