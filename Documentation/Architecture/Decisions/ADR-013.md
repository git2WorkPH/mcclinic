# ADR-013 — Durable onboarding delivery

Status: Accepted for local synthetic preparation, 2026-09-14; TASK-029 owner-approved sequence.

Account/token creation and encrypted delivery intent commit in one PostgreSQL transaction. Optional delivery adapter exposes a transaction enqueue hook; legacy callable filesystem delivery remains supported. Workers claim persisted leases, retry boundedly and use a stable outbox ID as sink idempotency key. No email, token, password or MFA secret enters audit metadata. A local filesystem sink accepts only explicitly configured `.test` domains. Provider activation, domain authentication and bounce processing remain production gates.

Delivery is at-least-once; the sink must deduplicate stable IDs. A lease expiry can cause concurrent delivery attempts, so database claiming alone is not an exactly-once guarantee. Successful acknowledgement and metadata audit commit together; failed acknowledgement is safely retried. Exhausted attempts retain records for inspection, with no purge. API responses do not wait for provider delivery.

This is additive to existing onboarding contracts. It does not grant support/clinical rights or claim production identity verification. Key versioning and secure transport are remaining TASK-029 work, not implicitly satisfied by an outbox.

## Versioned local key preparation

Optional `IDENTITY_KEYRING_FILE` selects a private 0600 JSON keyring with active key ID and retained 32-byte keys. Version-prefixed AES-GCM ciphertext authenticates the key ID as associated data. New encryption uses the active version; old versions remain decryptable from the backup. Legacy three-part ciphertext continues using the original onboarding-key. Neither file may be discarded while any retained record/backup needs it. This is a local custody adapter, not KMS protection. KMS wrapping/IAM/recovery and provider-backed validation remain unimplemented TASK-029 gates; no production readiness claim.

## Local preparation update — 2026-09-20

The earlier pending statements are historical. TASK-029 now includes a gated KMS SDK unwrap adapter with per-version encryption context; local tests inject the provider without AWS calls. Enrolled-account key-file rotation/restore is tested against PostgreSQL. Live KMS/IAM, wrapping and disaster recovery remain deployment gates.

Optional cookie transport uses an exact HTTPS Origin and JSON POST guard at the GraphQL boundary. The resolver returns only a nonsecret marker, even with aliases; HttpOnly Secure SameSite cookies carry the real token, and bearer fallback is disabled in this mode. The built web client remains contract-compatible. Local TLS browser tests verify the real transport. Original loopback bearer mode remains supported. Yoga's Node server context supplies the response for cookie headers ([official Express integration](https://the-guild.dev/graphql/yoga-server/docs/integrations/integration-with-express)). No public environment is enabled by this decision.
