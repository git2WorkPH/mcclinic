# ADR-017 — Parallel native Terraform candidate

Accepted for owner-approved local TASK-042 preparation, 2026-09-21. Native Terraform/HCL is an alternative to preserved CloudFormation, not a Python runtime replacement. Application remains TypeScript; new policy tests use Vitest. Existing Python checks and cfn-lint are retained as optional legacy tooling; no deletion approved.

Build a separate candidate environment with explicit names/account/region inputs and no AWS calls during fmt/validate/mocked tests. Never manage the same resource simultaneously with Terraform and CloudFormation. Before an actual environment chooses one owner, require account/budget/operator approval, encrypted locked remote state, plan review and deployment checks. prevent_destroy and AWS deletion protection are safeguards, not authorization; removing configuration can bypass Terraform lifecycle protection. Sensitive values may remain in Terraform state even when CLI output is redacted; origin header secret must be protected as a state-bearing secret and is never read during local tests. No secrets in tfvars examples or Git. Original cloud topology/retention decisions and production findings remain.

References: https://developer.hashicorp.com/terraform/language/tests/mocking ; https://developer.hashicorp.com/terraform/language/manage-sensitive-data ; https://developer.hashicorp.com/terraform/language/meta-arguments/lifecycle .

Implemented native root under infrastructure/terraform/staging with Terraform1.14.9/AWS provider6.65.0 and a signed-provider lockfile. This deliberately pinned CLI is not advertised as latest. Resource controls map to the four existing CloudFormation templates in infrastructure/terraform/README.md. The new API alarm resources remain present with actions disabled when desired_count=0, avoiding removal on deactivation. Image pulls use an explicitly supplied existing repository ARN; a separate immutable registry is retained for future releases. No images/assets uploaded or jobs executed. Mock plans and TypeScript policy parity are the local acceptance boundary; CloudFormation schema validation still uses optional legacy cfn-lint when that path changes.
