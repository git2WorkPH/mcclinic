# ADR-003 — Identity context and capability authorization
Status: Proposed
Date: 2026-09-10
Related requirements: FOUND-003, FOUND-004
Related tasks: TASK-003
Decision owner/acceptance evidence: project owner / pending

## Context
Personas are known but permissions, identity provider and clinic boundaries are not.

## Options
A. External identity provider with server-validated session/token plus application capabilities. B. Locally managed credentials with additional credential/recovery security responsibilities. Scope options: single-clinic context or explicitly authorized clinic-scoped context; neither implies full SaaS tenancy.

## Proposed decision
Provider/session choice deferred to FIND-002. Require actor/context passed into protected use cases and deny by default at resource/action boundaries, including direct GraphQL calls and print/export. Do not assign administrator clinical privileges implicitly.

## Consequences and validation
Approved allow/deny matrix and revoked/expired identity tests required. Validate provider failures and stale grants. No provider SDK or authentication implementation selected in this session.
No implementation or deletion is approved by this record. See [baseline](../BASELINE.md) and [findings](../../Assessment/INITIAL_ASSESSMENT.md).

## History
2026-09-10: initial proposal; no accepted predecessor or successor.

Within owner-authorized reversible development scope: Local seeded accounts, salted scrypt passwords, hashed opaque 8-hour revocable sessions and role/capability matrix defined in MVP assumptions. No external provider or production readiness claim.
