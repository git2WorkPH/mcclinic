# ADR-002 — Transactional audit, versioning and persistence
Status: Proposed
Date: 2026-09-10
Related requirements: FOUND-005, FOUND-006, FOUND-008
Related tasks: TASK-002, TASK-004
Decision owner/acceptance evidence: project owner / pending

## Context
Clinical writes need provenance and concurrency safety while preserving module ownership.

## Options
A. PostgreSQL transaction for clinical change/version plus durable audit (recommended), optional transactional outbox when approved delivery crosses boundaries. B. Best-effort audit after commit risks missing evidence. C. Full event sourcing increases replay/schema complexity.

## Proposed decision
Prefer relational current state plus retained versions/amendments, optimistic concurrency and scoped idempotency keys. Define unit-of-work ports in application layers; Prisma adapters handle transactions. Do not select retention, purge or per-document lifecycle policy here; FIND-005/006 block those details. No outbox runtime until a delivery requirement exists.

## Consequences and validation
Test failure between write/audit, stale version, retries, constraints and migrations in PostgreSQL Testcontainers. Reject silent finalized overwrites; do not expose database models across module boundaries.
No implementation or deletion is approved by this record. See [baseline](../BASELINE.md) and [findings](../../Assessment/INITIAL_ASSESSMENT.md).
